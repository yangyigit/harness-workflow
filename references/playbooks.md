# 剧本

路由时选一个，把「步骤」写进计划。标了「提示」的是可能要问我的官方技能，细节见 `signals.md`。选不出来就用「新功能」。

## 小改动（S）
信号：改文案、样式、配置，加参数，明确的一行修复
1. 找到改动点，读相邻代码，确认写法
2. 修改
3. 跑相关测试或最小验证

不提示任何技能。

## 修 bug
信号：报错、结果不对、功能失效、给了复现步骤或日志
1. 用 `diagnosing-bugs`（自动）：复现、缩小范围、假设、验证、修根因
2. 把失败测试留在代码库里
3. 用一句话说明根因

提示：无法复现时提示 `grill-me`，问清环境和步骤；同一模块第二次出 bug 时提示 `improve-codebase-architecture`；修的是公共代码时提示 `blast-radius`。

## 新功能（M）
1. 确定一句话验收标准，写进 `progress.md`。没给的话，提示 `grill-with-docs`
2. 读相关模块和 `docs/agents/conventions.md`
3. 用 `tdd` 实现（自动）
4. 跑「完成前必跑」
5. 提示 `code-review`
6. 更新 `progress.md`

## 大功能（L）
1. 提示 `grill-with-docs`。路线还看不清（绿地项目、目的地说不清）时改为提示 `wayfinder`，地图清晰后从第 2 步接上
2. 提示 `to-spec`。没配过 tracker 的，先提示 `setup-matt-pocock-skills`
3. 一个会话做不完时，提示 `to-tickets`
4. 提示 `implement`，逐个 ticket 推进
5. 涉及权限、迁移、并发时，提示 `interrogate`
6. 全部完成后提示 `retro`

## 重构
信号：重构、整理、抽离、拆分、太乱
1. 先确定行为不变的边界。没有测试的，先补特征测试，把现有行为锁住
2. 小步修改，每步都跑测试
3. 不夹带行为变化。发现 bug 先记进「待办」，单独修

提示：范围不清时提示 `improve-codebase-architecture`；完成前提示 `blast-radius`。

## 性能优化
1. 先测量，给出基线数字和测量方法
2. 用 `diagnosing-bugs`（自动）找瓶颈，只改瓶颈
3. 再测一次，对比前后数字。没有数字的「优化」不算完成

## 接手老项目 / 初始化
1. 提示 `init`。已有 `AGENTS.md` 就先读，再判断要不要 `split`
2. init 完成后，直接运行 `setup-matt-pocock-skills`，按它的提示逐项问我（见 `init.md` 第 8 节）

## 依赖升级
1. 读 changelog 里的破坏性变更
2. 一次只升一个主要依赖
3. 跑完整验证
4. 提示 `blast-radius`
5. 值得记录的取舍，按 `domain-modeling` 的格式写进 `docs/adr/`

## 问答 / 调研（不写代码）
读代码回答，附上文件路径。不改文件。问题较深时提示 `how`（怎么工作）或 `why`（为什么这样）。

## 开工 / 续接
信号：「继续 / 接着做 / 上次那个」
1. 读 `progress.md` 的当前任务和最近一条交接。我给了 handoff 文件就先读它
2. 跑「完成前必跑」，看基线
3. 用两三句话说明：上次做到哪、基线状态、打算从哪继续。然后直接开始，不等确认；基线是红的除外

## 收工
1. 更新 `progress.md`：当前任务进度、基线、待办，交接写一行
2. 提示 `retro`；要换工具或交给别人时改为提示 `handoff`
